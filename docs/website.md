# 发布下载页

推荐在 GitHub 仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。仓库已包含 `pages.yml`；推送到 `main` 或 `master` 后自动发布，也可在 Actions 页手动运行。工作流只发布网页、正式图片、许可和 `release/` 中的 APK，源码和构建目录不会进入网站。

如果偏好分支发布，可禁用该工作流，再选择 `Deploy from a branch`、`main`、`/ (root)`。两种方式都支持仓库子路径，下载链接无需修改。Actions 发布会自动注入仓库地址；分支发布可根据标准 GitHub Pages 地址推导仓库，自定义域名下请在 `assets/site/config.js` 填写 `repository: 'owner/repository'`。

本地预览在项目根目录运行 `python3 -m http.server 8000`，访问 `http://localhost:8000`。无需 npm、打包工具或模型依赖。

## 产品查看器与截图

下载页主标题为「Xiaomi V5」，副文案指向 18 Fold。页面仅保留标题、下载、交互预览和页脚，查看器按窗口剩余高度完整展开，没有独立的预览章节、安装区和内部滚动条。

产品查看器位于 `assets/viewer/`，恢复用户提供的 `iPhone-Duo-Readable` 原版机身和七种姿态。模型用于交互示意，不代表小米官方模型。原铰链模拟、惯性吸附、相机姿态混合与屏幕渐暗切换均保留；滑条采用原控件的拖动与弹性滑块，固定展示区域保留相机开合轨迹，复位后可从当前位置再次抓取并反向。前置摄像头按实机孔位适配：外屏居中、竖向内屏左上，横向时随设备旋转；倒 V 内屏熄灭，外屏显示日历。

首次展示会播放一次「合起 → 展开 → 半折」开合演示，右上「播放开合」可重播或停止。每段动作沿用原姿态弹簧、相机轨迹与铰链模拟；切换回折叠设计和复位也从当前姿态平滑过渡，抓住滑杆时才启用直接拖动。拖动、按键或切换姿态会立即中断演示，动画稳定后暂停渲染。启用系统「减少动态效果」时跳过自动演示，姿态切换保留短暂的屏幕渐暗换图。

连续开合同时恢复原版 `Wipe` 屏幕效果：折向一侧的画面逐渐模糊、变暗，展开后恢复清晰。范围由铰链角度驱动，使用原双次模糊采样与阴影函数；项目截图仍完整贴合屏幕。

内屏、竖屏、外屏和模式纹理以项目原生运行截图为基础。半折姿态以 Android 系统真实运行的上下分屏为底图：笔记在上、计算器在下；笔记状态栏与工具图标已清理，文字上移至摄像头下方。展开桌面移除 Paint 图标后有 11 个网格应用与 4 个 Dock 应用，互不重复；提醒事项的空状态改为「给18Duo在GitHub一颗Star吧～」。资源库展示原生字母列表。截图捕获副本、包名映射、测试输入与网页修饰范围见 `assets/screenshots/SOURCE.md`，这些截图不是未改动 Release APK 的统一捕获。

页面先显示截图，在查看器进入视口后加载 3D。删除与当前静态屏幕展示无关的离屏壁纸场景和纹理，复用已有屏幕资产，关闭调试绘制；动画完全稳定后停止更新，离开视口和后台时暂停。WebGL 失败时保留可切换的真实截图。具体适配见 `assets/viewer/SOURCE.md`。

网站运行只需要静态文件，无需 npm 或在线模型服务。`viewer-runtime.js` 与 `viewer.css` 是嵌入适配源码；`v/` 保存参考运行时、模型和场景资源，第三方素材仍保留原权利归属。参考素材不包含在本项目 MIT 代码授权范围内。

查看器的模型与场景配置同时提供无损 `.gz` 副本，支持原生解压的浏览器优先读取。修改 `assets/viewer/v/` 中的 `.bin`、`.gltf` 或 `.lsd` 后，运行 `python3 scripts/prepare-viewer-assets.py` 再预览或提交；GitHub Actions 发布时会重新生成。浏览器不支持解压，或副本缺失、损坏时自动读取原文件。内屏开合效果根据触摸设备和 GPU 限制分配缓冲，并缓存稳定的纹理；采样失败时直接显示原截图。

## 下载统计

`assets/site/config.js` 已配置一个从 0 开始的 [Abacus](https://abacus.jasoncameron.dev/) 公共计数器。网页加载只读取计数，点击带 `data-download` 的下载链接才增加计数。数量由远端保存，所有访客看到同一统计；本地预览不计数。

- **口径**：下载按钮点击，同一浏览器 24 小时内计一次。并非精确人数、下载完成数或安装数。
- **去重**：浏览器本地只保存最近一次计数时间，不创建用户 ID，不上传设备信息。禁用存储时使用当前页面内存去重；清除数据或换浏览器后会重新计数。
- **故障**：网络失败显示“下载统计暂不可用”；请求有 8 秒上限，下载链接始终独立生效。连接中断可能造成少计或重复，公共接口也无法完全阻止他人刷量。
- **第三方**：浏览器直接连接 Abacus，正常网络连接会向服务提供者暴露 IP；本项目不采集 IP、不发送 Cookie、页面地址或个人身份。服务的可用性由其运营者决定；官方说明计数器连续 6 个月未访问会过期。

发布新版本时修改 `version`、下载链接与 `counter.key`（如 `apk-v1-1-0`）。新 key 首次点击自动从 1 开始，尚未创建时会显示统计不可用；如需从 0 展示，可先调用官方 `/create/{namespace}/{key}?initializer=0`。创建时返回的管理密钥应保存在仓库之外，切勿放入前端。Fork 此项目时更换 `namespace`，避免共用原项目计数。

所有下载链接添加 `data-download`；完整统计文案使用 `data-download-stat`，只展示数字则使用 `data-download-count`。按顺序加载 `config.js` 和 `counter.js`，均可设置 `defer`。

## 改用 GitHub Release 下载次数

把 APK 上传到公开 GitHub Release，下载链接改为对应 Release 文件地址，然后将 `counter.provider` 改为 `github-release`，并在 `repository` 填入 `owner/repository`。标准 GitHub Pages 项目地址也可自动识别仓库。页面读取 GitHub 最新 Release 内所有 `.apk` 资产的 `download_count`，文案自动改为“GitHub 安装包下载”，无需密钥。仓库根目录 APK 的直接下载无法被 GitHub Release API 统计。
